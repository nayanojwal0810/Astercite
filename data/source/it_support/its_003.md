# MFA and Password Reset Procedure

## Purpose and Scope
This procedure outlines the security standards, verification steps, and turnaround targets for resetting multi-factor authentication (MFA) tokens across Aster Systems accounts. Robust authentication protocols protect enterprise resources from credential stuffing and social engineering attempts while providing a predictable path for users to recover lost or replaced authenticator devices. This document applies to all staff members requesting MFA assistance and IT Support personnel processing reset tickets.

## MFA Reset Verification
Authentication resets involve sensitive security credentials and require thorough validation to prevent unauthorized account takeover.
<!-- fact_id: ITS003_F01 -->
To request an authentication reset, both identity verification and a service ticket are required before support personnel may clear registered security tokens. Confirming identity through formal verification and tracking the request within a ticket ensures procedural integrity.

## MFA Reset Resolution
Balancing rigorous security verification with prompt user access restoration minimizes unproductive downtime for affected employees.
<!-- fact_id: ITS003_F02 -->
IT Support operates under a target resolution turnaround of 4 business hours to complete verified MFA reset requests. This window allows technicians to complete necessary validation checks and assist the user with re-registering their authentication device.

## Prohibited Reset Practices
Restricting communication channels used for security credentials prevents unauthorized interception of authentication tokens.
<!-- fact_id: ITS003_F03 -->
Transmitting temporary reset codes or security bypass credentials by email is strictly prohibited under enterprise security guidelines. Avoiding email delivery prevents compromised inboxes from being used to bypass multi-factor authentication defenses.

## Exceptions and Related Documents
This document serves as an independent technical security standard. It maintains no external cross-document dependencies, incoming workflows, or outbound policy links.

## Revision History
Version v1 is effective from 2026-11-01. This initial procedure establishes identity verification requirements, a 4 business hours resolution target, and strict prohibitions on email credential delivery for Aster Systems accounts.
