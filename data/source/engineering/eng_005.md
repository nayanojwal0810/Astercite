# Troubleshooting Known Error Codes

## Purpose and Scope

This troubleshooting guide documents standardized diagnostic steps and resolution procedures for frequently encountered application error codes across Aster Systems services. By maintaining an authoritative reference for recognized system exceptions, engineering and technical support personnel can rapidly diagnose recurring failure modes, prevent redundant investigation, and restore healthy service states. This guide applies to software engineers, site reliability teams, and Tier-2 technical support specialists.

## E1001 Authentication Error

<!-- fact_id: ENG005_F01 -->

Error code E1001 indicates an expired authentication token when an active session or API client attempts to access protected service endpoints. When this condition is detected in application logs or client responses, the immediate resolution is to instruct the user or service account to sign in again to obtain a fresh, cryptographically valid session token.

Engineers investigating E1001 alerts should verify that token expiration timestamps adhere to identity service standards and confirm that client clocks remain synchronized with network time protocol servers.

## E2003 Retry Procedure

<!-- fact_id: ENG005_F02 -->

Error code E2003 signifies a transient downstream rate-limiting condition or temporary socket saturation across internal microservice communication channels. Automated clients and backend workers encountering an E2003 exception must enforce a mandatory retry delay of 60 seconds before reissuing the failed request.

Applying this 60-second backoff interval allows congested service queues to drain and prevents cascading load amplification against struggling database backends.

## E3002 Billing Error

<!-- fact_id: ENG005_F03 -->

Error code E3002 indicates that billing synchronization is pending across payment processing queues and accounts ledger records. When this error occurs during subscription processing or invoice generation, the responding engineer must check reconciliation status in the payment gateway ledger before attempting any manual database mutation or retry.

Verifying the synchronization state prevents duplicate invoice creation, ensures accurate tenant ledger balances, and confirms whether automated reconciliation jobs are actively processing the transaction.

## Exceptions and Related Documents

Unlisted error codes or unhandled runtime panics that do not match documented error signatures must be escalated to the on-call engineer for code-level triage.

This troubleshooting guide functions as an independent technical reference. It maintains no external cross-document dependencies, incoming workflows, or outbound policy links.
